为什么是跑马灯

  1. 不抢当前会话。不弹窗、不切走、不打断你手上这轮 —— 只占侧栏一行。
  2. 标题本来就是省略号。审批内容比原标题长得多，跑马灯顺带解决了「看不全」。
  3. 状态一眼可辨。琥珀色只用于待审批，和珊瑚色的「运行中」分开，不打架。
  4. 点一下就到。点这行 → 切过去 → 审批面板已经在最上面。

行为规则 实现时按这几条走

只在「非当前会话」出现当前会话的审批本来就在主区里，再滚一遍是噪音。
标题超长才滚，短标题不滚跑马灯的触发条件是 scrollWidth > clientWidth；不溢出就正常省略。
一条请求对应一条，不合并同会话连续多条只显示最上面那条；多个会话各自滚各自的。
hover 暂停鼠标停在行上就停住，移开继续 —— 方便读完整句再点。
回答完立即停答复 / 切到该会话 / 进程退出 / 会话被删 —— 四个出口都要把标记撤掉。
减少动态效果时不滚prefers-reduced-motion 下标题静态省略，只留「待审批」胶囊，状态信息不能靠动效单独承载。
折叠起来的会话也要冒头待审批的会话被「展开其余 N 个」收进去时，自动展开该组；组头再加一颗小角标，免得列表一长又看不见。
匀速，不按标题长短变速时长按文本宽度算（约 26px/s），长标题不会滚得飞快。每轮开头停 0.8s，读完再走。
