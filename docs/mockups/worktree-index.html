并行会话 + git worktree

三种界面形态，共用同一套设计 token。核心结构是会话标签 + 工作树信息条； 每条会话绑定一个独立 worktree（独立目录 + 独立分支），结束后可以合并或丢弃。 运行中的会话用珊瑚色，分支相关元素统一用冷蓝色，两者不抢。

取舍： A 成本最低，侧栏和标签就能表达「三条会话在并行」，但同一时刻只能看一条； B 最适合盯着两个代理互相配合，代价是每条会话只剩半宽，长工具输出会频繁换行； C 是 A/B 共用的入口。 我的建议：先做 A + C，把 worktree 生命周期跑通（创建 / 合并 / 丢弃）， 分屏 B 作为下一档，等真的有人同时盯两条会话再加。
