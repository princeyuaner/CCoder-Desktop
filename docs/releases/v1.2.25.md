## 本次更新

### 改进

- **拖入文件自动识别编码**：拖进 / 选进输入框的文本文件不再一律按 UTF-8 读取。按字节识别 BOM、无 BOM 的 UTF-16 / UTF-32、严格 UTF-8、chardet 传统编码，识别不出来时回落到 GB18030；常见场景包括 GBK、Big5、Shift-JIS、EUC-JP、EUC-KR 和各类 Windows / ISO 单字节编码。
- **引用卡标出源编码**：非 UTF-8 的文件会在输入框和执行记录里的引用卡上显示类似 `GBK` 的徽标；编码信息随 `<ide_reference>` 一起写入会话记录，历史回放和「编辑重发」也能还原。
- **宽字符文件不再被当成二进制**：无 BOM 的 UTF-16 / 32 文件此前会因头部出现 NUL 被跳过，现在会正常读出；真正含 NUL 的二进制文件仍然跳过。
- **截断更干净**：文件超过 512 KB 被截断时，如果切口正好落在多字节字符中间，末尾不会再留下一个替换符。

### 注意

- 纯 CJK、无 BOM 且完全不含 ASCII 的 UTF-16 文件在统计上无法与 GB18030 等旧编码稳定区分，仍可能按 GB18030 读成乱码。
- 编码识别只用于这次读取，不会写回磁盘；这条路径不提供手动改选编码的入口，需要改选请把文件放进工作区，用 IDE 打开。
- 内置 IDE 的编码识别逻辑保持不变。
